# 部署手册

> 目标：拿到一个**评审能持续访问**的公网地址，并配上评审专用账号。
> 本文给出三条路线，先看对比再选，不要跳着做。

---

## 一、先决策：三条路线怎么选

| | A. 云主机（推荐） | B. 家里机器 + Tunnel | C. 无 Docker 直跑 |
|---|---|---|---|
| 成本 | 学生机约 10–30 元/月 | 0 元 | 同 A |
| 稳定性 | 高（机房 7×24） | **取决于你的机器不关机、不断网** | 高 |
| 首次耗时 | 1–2 小时 | 40 分钟 | 40 分钟 |
| 需要什么 | 云账号 + 一点预算 | Cloudflare 账号 | 一台常开的机器 |
| 风险 | 费用 | 评审期某天家里断电就失联 | 环境漂移 |

**建议选 A。** 赛题原文要求「评审期间须保持服务可用」，而这些材料从提交（11-18）到评审意见发布（次年 1 月底）有两个多月。用家里机器扛两个月的概率不高，一旦掉线就是"在线演示不可用"。

如果确实没有预算，选 B 但务必做两件事：机器设置永不睡眠、开机自启。

---

## 二、路线 A：云主机

### A1. 买机器

| 项 | 建议 |
|---|---|
| 规格 | 2 核 4G 起（解析 507 页文档峰值内存约 300MB，但向量模型加载要 1–2G） |
| 系统 | Ubuntu 22.04 / 24.04 LTS |
| 磁盘 | 40G 起（模型缓存约 700MB + 数据） |
| 带宽 | 3M 够用（页面很小，PDF 按需加载） |

安全组 / 防火墙放行：**22**（SSH）、**80**、**443**。

### A2. 装 Docker

```bash
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
sudo usermod -aG docker $USER   # 重新登录后生效
```

### A3. 拉代码并配置

```bash
git clone <你的仓库地址> evidence
cd evidence
cp .env.example .env
nano .env
```

`.env` 里必须改的：

```ini
AUTH_ENABLED=1
EVIDENCE_USERS=demo:换成你的演示密码,reviewer:换成你的评审密码
EVIDENCE_SECRET=用 openssl rand -hex 24 生成
DEEPSEEK_API_KEY=sk-...          # 有就填，没有也能跑（降级为抽取式）
HF_ENDPOINT=https://hf-mirror.com  # 国内强烈建议
API_BASE=http://api:8000
```

> **`EVIDENCE_SECRET` 不要用示例值**。它决定会话令牌能否被伪造。

### A4. 启动

先做一次**静态自检**（不需要 Docker，检查 COPY 源路径、compose 引用、
环境变量是否齐备）：

```bash
python scripts/check_deploy_static.py
```

25/25 通过再往下走，能省掉"构建到一半才报错"的时间。

```bash
docker compose up -d --build
docker compose logs -f api     # 首次会下载约 640MB 模型，等它出现 Uvicorn running
```

看到 `Uvicorn running on http://0.0.0.0:8000` 后，另开一个终端验证：

```bash
curl -s localhost:8000/api/health
# {"ok":true,"llm":"deepseek","chunks":0}
```

`chunks` 为 0 是正常的——**库是空的**。把论文放进去：

```bash
# 方式一：用容器内的脚本批量导入（推荐）
docker compose exec api python /app/scripts/fetch_corpus.py
docker compose exec api python /app/scripts/index_cli.py build "data/pdf/*.pdf"

# 方式二：从本机上传（走 API）
curl -F "file=@1706.03762v1.pdf" http://<你的域名>/api/papers
```

### A5. 配域名与 HTTPS（Caddy，最省事）

```bash
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt install -y caddy
```

`/etc/caddy/Caddyfile`：

```caddy
evidence.example.com {
    reverse_proxy /api/* localhost:8000
    reverse_proxy /figures/* localhost:8000
    reverse_proxy localhost:3000
}
```

```bash
sudo systemctl reload caddy
```

Caddy 会自动申请并续期 Let's Encrypt 证书。记得把域名 A 记录指到服务器 IP。

### A6. 开机自启与备份

`docker-compose.yml` 里已为两个服务设置 `restart: unless-stopped`，Docker 服务本身开机自启后容器会自动拉起。

```bash
sudo systemctl enable docker
```

数据都在 `evidence-data` / `evidence-cache` 两个卷里。定期备份：

```bash
docker run --rm -v evidence_data:/data -v $(pwd):/backup alpine \
  tar czf /backup/evidence-data-$(date +%F).tar.gz -C /data .
```

### A7. 更新代码

```bash
git pull
docker compose up -d --build
docker compose exec api python /app/scripts/verify_all.py   # 更新后跑一遍
```

## 三、路线 B：家里机器 + Cloudflare Tunnel

### B1. 安装 cloudflared

Windows：

```powershell
winget install --id Cloudflare.cloudflared
```

Linux：

```bash
curl -L https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64 -o /usr/local/bin/cloudflared
chmod +x /usr/local/bin/cloudflared
```

### B2. 建隧道

```bash
cloudflared tunnel login          # 浏览器授权
cloudflared tunnel create evidence
cloudflared tunnel route dns evidence evidence.example.com
```

`~/.cloudflared/config.yml`：

```yaml
tunnel: evidence
credentials-file: C:\Users\<你>\.cloudflared\<tunnel-id>.json
ingress:
  - hostname: evidence.example.com
    service: http://localhost:3001
  - service: http_status:404
```

### B3. 让前后端都跑起来

先在本地把两个服务起好（`scripts/start.ps1`），并确认 `web/next.config.mjs` 的代理指向 `http://127.0.0.1:8000`。

### B4. 常驻

```powershell
cloudflared service install        # 注册为 Windows 服务
Start-Service cloudflared
```

Linux：`sudo cloudflared service install && sudo systemctl enable --now cloudflared`

### B5. 必须做的两件事

1. **电源设置**：控制面板 → 电源选项 → 睡眠设为"从不"。
2. **开机自启**：`cloudflared` 服务 + `scripts/start.ps1` 加进启动项（或用任务计划程序，触发器选"登录时"）。

## 四、路线 C：不用 Docker 直接跑

Linux（systemd）：

```ini
# /etc/systemd/system/evidence-api.service
[Unit]
Description=Evidence API
After=network.target
[Service]
WorkingDirectory=/opt/evidence
ExecStart=/opt/evidence/.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --app-dir /opt/evidence/backend
Restart=always
[Install]
WantedBy=multi-user.target
```

前端同理，`ExecStart=/usr/bin/node node_modules/next/dist/bin/next start -p 3000`，`WorkingDirectory=/opt/evidence/web`。

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now evidence-api
```

Windows：用 `scripts/start.ps1`，再用任务计划程序设置为"登录时运行"。

## 五、评审账号

赛题要求「如需登录，须提供评审专用测试账号」。当前实现：

| 账号 | 密码来源 | 用途 |
|---|---|---|
| `reviewer` | `.env` 的 `EVIDENCE_USERS` | 写进提交材料，交给评审 |
| `demo` | 同上 | 演示视频里用 |

配置方式（`.env`）：

```ini
AUTH_ENABLED=1
EVIDENCE_USERS=demo:演示密码,reviewer:评审密码
```

关闭认证仅用于本地开发：

```ini
AUTH_ENABLED=0
```

> 提交材料里的账号密码，建议与演示视频中出现的保持不同，避免视频公开后被滥用。

## 六、部署后自检（必做）

不要靠手点判断"应该没问题"。对着公网地址跑：

```bash
python scripts/check_deploy.py https://evidence.example.com \
  --user reviewer --password 你的评审密码
```

它会验证 9 项：健康检查免登录、索引非空、评审账号可登录、会话有效、文献库可读、
问答返回带锚点的有据回答、四个页面可达。

```
[PASS] 健康检查可访问（免登录）
[PASS] 已建立索引
[PASS] 评审账号可登录
...
9/9 项通过
部署自检通过，可以把地址交给评审。
```

**全部通过再把地址交出去。** 任何一项 FAIL，按下面的表排查。

## 七、常见故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 页面 502 / 空白 | 前端没起或代理地址错 | `docker compose ps`；检查 `API_BASE` |
| `/api/*` 返回 401 | 认证已开但没登录 | 正常行为；用 `reviewer` 账号登录 |
| `/api/*` 返回 404 | 反向代理只转了 `/`，没转 `/api` | 检查 Caddy/nginx 的路径规则 |
| 健康检查 `chunks: 0` | 库是空的 | 导入论文并建索引（见 A4） |
| 问答一直"证据不足" | 索引没建，或问题与库无关 | 先 `/api/papers` 确认库非空 |
| 首次启动卡在下载模型 | 访问 HuggingFace 慢 | `.env` 设 `HF_ENDPOINT=https://hf-mirror.com` |
| 检索/解析很慢 | CPU 太弱 | 2 核是最低要求；541 页解析约 3–6 分钟 |
| 上传 PDF 报 500 | 文件损坏或加密 | 换一个 PDF 试；加密 PDF 不支持 |
| 容器内存被 OOM | 向量模型加载 + 并发解析 | 4G 内存起步；避免同时上传多篇长文档 |

## 九、已知限制（如实说明）

- **Docker 镜像未做镜像级验证**：开发机未安装 Docker，`Dockerfile` 与
  `docker-compose.yml` 按标准写法给出，依赖组合已在本地虚拟环境完整跑通，
  但未在真实 Docker 中构建过。若 `compose build` 报错，优先检查
  `libgl1 / libglib2.0-0` 这类系统库（后端 Dockerfile 已装）。
- **认证为演示级**：密码明文存于环境变量，无哈希、无失败锁定、无轮换策略。
- **单实例**：SQLite + 本地文件，不支持多副本水平扩展；评委并发很低，够用。
