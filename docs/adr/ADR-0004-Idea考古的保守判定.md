# ADR-0004 Idea 考古：没有模型时不许说"已解决"

- 状态：已采纳
- 日期：2026-10-24
- 相关：模块五、评分项「学术算法与图谱挖掘创新」10%

## 背景

赛题要求「自动排除已被后续论文解决的旧 idea」。实现路径是：抽取 Future Work 陈述 →
语义聚类 → 只在**晚于原论文**的文献中检索 → 判断是否已被解决。

## 发现的问题

第一版用重排分做单一判据：分数 ≥ 1.0 判「疑似已解决」，否则「未发现解决证据」。
跑 37 条陈述后，有 8 条被判「疑似已解决」，人工抽查发现**全部是误判**：

| 原陈述 | 系统判定 | 实际 |
|---|---|---|
| To facilitate future work on transfer learning for NLP, we release our data set… | 已解决（证据：GPT-3 引言，score 2.17） | 这是数据声明，根本不是设想 |
| In future work, we expect it could be fruitful to consider combinations… | 已解决（证据：GPT-3 Related Work，score 1.33） | 只是相关工作相近 |

根因：**重排分衡量的是"语义相关"，不是"问题已解决"**。相关性高 ≠ 问题被解决，
这两件事之间隔着一次因果推理，只有模型能做，交叉编码器做不到。

## 决策

**按可用能力分级判定，宁可漏报不可误报：**

| 条件 | 结论 |
|---|---|
| 有 LLM | 交给 FUTURE_JUDGE 提示词判定三态，并要求逐条标注证据编号 |
| 无 LLM，分数 ≥ 阈值 | **部分相关证据**（不下"已解决"结论） |
| 无 LLM，分数 < 阈值 | 未发现解决证据 |
| 无更晚文献 | 无法判定（无后续文献） |

另加一条负向过滤：`facilitate future work` / `we release our data` 这类
"为后续工作提供便利"的表述不是设想，直接排除。

## 为什么这个取舍是对的

把一个仍有价值的研究方向判成"已解决"，用户会因此放弃它——这是这类工具
最有害的失败模式，且用户无从察觉。反过来，漏报一个已解决的 idea，
最坏结果是用户多花时间确认，代价可承受。

**错误不对称，所以阈值必须偏向保守。**

## 顺带解决的性能问题

Idea 考古要对 37 条陈述各做一次检索+重排。首版耗时 **11 分 43 秒**，
定位到重排单次 5.1 秒（12 候选 × 整块文本）。三项调整：

1. 重排输入截断到 600 字（交叉编码器只需读关键片段）；
2. 候选池 12（不能再降——降到 8 会导致「GPU 型号」那条检索失败）；
3. 重排 session 线程数设为 CPU 核数。

结果：单次检索 4.97s → 1.58s，全流程 11m43s → 85s，
且 6/6 检索验收用例保持通过。

注：截断到 400 字时会砍掉关键句（"8 NVIDIA P100 GPUs" 落在 400 字之外），
故 600 是实测下限，不可再降。
