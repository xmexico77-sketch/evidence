# ADR-0005 作者-年份式引用的配对策略

- 状态：采纳
- 日期：2026-10-26
- 相关文件：`backend/app/parsing/refs.py`

## 背景

IEEE / CVPR 模板的正文引用是编号式（`[32]`），我们有 `parse_citations` 直接解析。
ACL / ICML / NeurIPS 模板没有编号，只有作者-年份式：

```
Transformers (Vaswani et al., 2017) have achieved ...
```

只认 `[n]` 的后果是这类论文的引用数恒为 0，「引用双向跳转」整体失效。
实测 CLIP（ICML）与 Longformer（ACL）在接入前的引用数都是 0。

## 决策

分两级匹配，逐级放宽：

1. **首作者姓 + 年份**（强证据）
   `_first_surname` 识别三种作者顺序：`姓, 名` / `名 姓,` / `J. Smith`。
2. **作者区任意姓 + 年份**（弱证据）
   取参考文献条目中"年份之前"的文本作为作者区，其中出现的任何姓氏
   都能与该年份配对。之所以需要这一级：ACL 模板的参考文献条目
   经常被切在半途（例如 `Ravula, Sumit Sanghai, …` 实际是上一条的续行），
   首作者信息丢失，只靠第 1 级配不上。

两级都失败则不生成引用——**宁可少一条跳转，也不指向错误的文献**。
这一点与抗幻觉的取舍一致：错误的溯源比没有溯源更糟。

## 实测

| 论文 | 模板 | 参考文献数 | 接入前引用数 | 接入后 |
|---|---|---|---|---|
| 2103.00020 CLIP | ICML | 194 | 0 | 39 |
| 2004.05150 Longformer | ACL | 53 | 0 | 11 |
| 1706.03762v1 Transformer | 编号式 | 36 | 54 | 54（不受影响） |

## 已知不足

Longformer 正文有 48 处 `(X et al., YYYY)`，只配上 11 处。原因是
**参考文献条目切分本身丢内容**：该文实际约 60 条，我们切出 53 条，
且多条被从中间截断，导致大量姓氏根本不在参考文献文本里——
这不是配对逻辑能补的，属于切分算法的短板。

影响面：ACL 新模板的论文在该篇上的引用跳转覆盖偏低；编号式论文与
演示所用的 Transformer 论文不受影响。已记录在技术文档「已知限制」。

## 后续

若要彻底解决，需要为作者-年份式参考文献单独写一个切分器：
以"年份 + 句点"作为条目的强边界（`2017.` `2020.`），
而不是靠"行首像作者名"来断句。这会改动 `parse_references` 的主路径，
风险高、收益集中在少数模板，暂不做。
