# ADR-0001 中文提问如何检索英文论文：加一层查询扩展

- 状态：已采纳
- 日期：2026-10-24
- 相关：模块二（抗幻觉 RAG）、评分项「混合检索（Dense/Sparse）策略是否合理」8%

## 背景

测试集论文全部是英文，而使用者会用中文提问。原设计的检索链是
`BM25 + bge-small-en-v1.5 稠密向量 → RRF → bge-reranker-v2-m3 重排`。

## 问题（实测，非推测）

在 v1/v7 两篇论文（58 块）上跑 6 条中文事实查询，**首轮 2 条失败**：

| 查询 | 期望事实 | 结果 |
|---|---|---|
| 标签平滑的取值是多少？ | `label smoothing of value ϵls = 0.1` | FAIL，top1 落到 Scaled Dot-Product Attention |
| 用了多少个注意力头？ | `h = 8 parallel attention layers` | FAIL，top1 落到 Attention Visualizations |

用 `db_grep` 确认：**两处内容都在索引里**，失败发生在召回阶段，不是解析丢失。

根因：
1. `bge-small-en` 是英文模型，对中文 query 生成的向量几乎无意义，稠密通道等于失效；
2. BM25 按 token 匹配，中文词切不出对应英文词，稀疏通道也失效；
3. 多语言 CrossEncoder 只能在**已有候选**里重排，候选集里没有正确块，它也无能为力。

## 决策

在检索前加一层 **查询扩展**，把中文提问映射到英文术语空间，再进入双通道召回。

三级策略（按可用性递降）：
1. **LLM 扩展**（有 DeepSeek Key 时启用）：处理任意领域术语、同义改写；
2. **术语表扩展**（离线保底）：内置约 70 个学术/深度学习高频术语，最长优先匹配；
3. **原样查询**：无扩展时保底。

关键设计：扩展只影响**召回**，最终排序仍由多语言 CrossEncoder 决定。
因此术语表不够精确只会降低召回率，不会直接产生错误答案——安全性由重排层兜住。

## 结果

同一组 6 条查询，**6/6 命中且全部落在 top-3**。
「标签平滑」的正确锚点为 `1706.03762v1 · p7 · §Regularization`。

## 代价与限制

- 术语表是手工维护的，覆盖不到冷门领域词（如特定材料学名词）。这是 LLM 扩展要解决的问题，也是接入 Key 后要替换的第一处。
- 若论文正文本身是中文，该扩展反而会引入噪声（此时应跳过）。已在代码中以「查询含 CJK」为触发条件，后续需补「论文语种」判断。
