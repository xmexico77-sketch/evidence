# ADR-0002 分栏与阅读序：降到字符级重建，不用 PyMuPDF 的 block/line

- 状态：已采纳
- 日期：2026-10-24
- 相关：模块一（PDF 细粒度解析）、评分项「多模态与细粒度文档解析」7%

## 背景

学术 PDF 多为双栏。阅读序错了，后面全部连带错：段落被拼接到别的章节、
锚点指向错误位置、问答召回到语义断裂的块。

## 问题（实测）

1. **行级分栏判定不可靠**。PyMuPDF 的 `get_text("dict")` 会把左右两栏**同一基线**
   的文字合并进同一个 `line`，于是"整行横跨中缝"，任何基于行的左右统计都失效。
   我们的第一版探针正是因此**误判 v1 为双栏**（实际 v1 正文是单栏，仅参考文献页为双栏）。
2. **词间空格丢失**。LaTeX 生成的 PDF 常不写空格字符，靠字符坐标偏移表示词距，
   直接拼接 span 文本会得到 `TheencoderiscomposedofastackofN=6`。
3. **竖排水印污染层级**。arXiv 左侧的竖排编号被拆成单字行（`uJ 2`、`C .s`），
   字号还很大，会被误判成标题。

## 决策

放弃 block/line 级处理，改为**字符级重建**：

1. 从 `rawdict` 取字符及其 bbox；**按 `line["dir"]` 过滤非水平文本**（解决水印）；
2. 按基线聚成行，容差 0.5×字号（容纳上下标）；
3. 行内按横向间隙切段：`gap > 1.15×字号` 视为栏/块断裂（解决跨栏粘行）；
4. 段内 `gap > 0.18×字号` 补空格（解决空格丢失）；
5. 段作为最小单元参与分栏判定与阅读序重建：通栏块切横向分隔带，带内先左后右；
6. 标题行（编号行或短加粗行）**绝不并入下一段正文**——否则出现
   `5.3 Optimizer We used the Adam optimizer…` 这种粘连块。

## 结果

- v1：标题 25 个、章节 19 个（1/2/3/3.1/3.2/3.2.1/3.3…7）、参考文献 41 条、引用 54 处；
- 三句长正文断言逐字匹配通过（证明空格重建正确）；
- `scripts/verify_parse.py` 全部断言通过。

## 代价与限制

- 字符级遍历比 block 级慢，541 页书籍需配合懒解析与分批索引进度；
- 已知缺陷：v1 的 3.2.2（Multi-Head Attention）未被识别为标题——该页顶部是
  图注用的重复小标题，真实编号在上一页底，属跨页标题切分问题，待后续修；
  参考文献编号 37/38 缺号（跨栏续行合并所致）。
